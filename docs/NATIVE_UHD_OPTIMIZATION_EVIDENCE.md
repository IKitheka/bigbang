## What changed

In `shaders/postprocess/primordial_volume.frag`, a density mask that is exactly zero now returns zero before five otherwise unused noise fields are evaluated. Two plasma FBM fields are evaluated only when their uniform contribution is nonzero; that contribution begins after 48 seconds. The sample count, ray depth, field definitions, camera, exposure, bloom, color grading and Solar System implementation were not changed. These guards remove work with zero mathematical contribution rather than reducing native resolution or detail.

The workflow uses the same compiled binary and driver for both shader versions. It substitutes the reference shader only during each comparison, alternates capture order, restores the candidate in a finally block, and verifies a clean source tree afterward. It also verifies that all other source and shader files match the reference revision. Images are generated by the C++ OpenGL renderer, then decoded to RGB24 by FFmpeg for byte comparison.

## Verified results

The clean Ubuntu Release build, native CTest regression and all eleven Python delivery regression tests passed. All 24 reference/candidate comparisons had identical decoded RGB bytes: zero differing channels and maximum channel delta zero.

Twenty-one comparisons used 640x360 at 4.5, 6, 12, 17.9666667, 18, 18.0333333, 22, 30, 42, 45, 48, 49.9666667, 50, 50.0333333, 54, 56, 210, 250, 260, 280 and 292 seconds. These include frames around both opening handoffs, the galaxy field, molecular bridge and approved finale. Three further comparisons were rendered natively at 3840x2160:

| Sample time | Reference process time | Candidate process time | Identical decoded RGB |
|---|---:|---:|---|
| 6s | 15.101s | 8.685s | Yes |
| 30s | 17.507s | 11.337s | Yes |
| 50s | 20.355s | 18.655s | Yes |

These are single-process still-capture timings, including context creation, shader compilation/cache effects, rendering, readback and PNG encoding. They are not isolated GPU timings or a statistically controlled full-film benchmark. The sampled 6s and 30s process times decreased by approximately 42% and 35%, respectively. Do not extrapolate those percentages to the whole film or to another machine.

## Actual rendering resources

On this Ubuntu 24.04 hosted runner, the default OpenGL query with both software-driver override variables removed reported llvmpipe (LLVM 20.1.2, 256 bits), Mesa 25.2.8 and `Accelerated: no`. The capture used the same software renderer, OpenGL 4.5 Core and GLSL 4.50. The device listing contained card1 but no render node, and nvidia-smi was unavailable. The repository's self-hosted Runners settings showed no configured runners. This does not establish the hardware or capabilities of the user's local computer or a separately provisioned GPU machine.

## Acceptance limits and next production gate

Pixel identity at these sample times supports retaining this optimization on this driver. It does not establish identity for every frame or other drivers, approve the artistic quality, demonstrate temporal continuity of a finished film, or verify soundtrack synchronization. Longer native UHD motion previews, independent full-film audiovisual review, all 9,000 final frames, final audio assembly, delivery documents and persistent Release downloads still require completion. Existing lower-resolution footage must not be substituted for native UHD frames.
